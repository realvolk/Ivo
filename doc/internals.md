# Stage 2 Internals

Platform-neutral parts of Stage 2. UEFI-specific notes in `uefi.md`.

## Startup

`.bss` isn't loaded from disk; the linker places sections and firmware
loads them.

## Memory layout

No fixed addresses. Firmware allocates. `vmlinuz`, `initrd`, and
`ivo/config.toml` read from the boot device. On a LUKS install,
`hal_init` retargets the boot device at the LUKS partition before the
filesystem layer runs. On a plaintext install, the boot device stays
at the ESP.

Argon2id working memory comes from `mm_alloc`, not the `.bss` heap
directly. A default LUKS2 volume asks for 1 GiB; the small heap falls
through to `hal_allocate_pages` for anything that large.

## HAL boundary

`hal.h` defines the platform contract. Implementations: `uefi.c`,
`uefi_kernel.c`. Everything above the HAL is UEFI-only.

`boot_context_t.boot_lba` is the sector offset of the filesystem
within the block device. Set to 0 for the ESP, or to the LUKS
partition's start when the device is retargeted.

### Disk I/O

Uses `EFI_BLOCK_IO_PROTOCOL` with cached `MediaId` and `BlockSize`.
Reads chunked to 128 sectors per `ReadBlocks` call.

### Memory map

`hal_get_e820` returns 20-byte E820 entries, translated from
`EFI_MEMORY_TYPE`.

### Allocation

Wraps `AllocatePages` with `AllocateAnyPages` and
`AllocateMaxAddress`. Falls back to `AllocateAnyPages` if the below
cap fails.

### Console

`hal_putchar` routes through `ConOut->OutputString`. Used only before
the framebuffer is up and in panic paths.

`hal_getchar` polls `ReadKeyStroke` and translates UEFI scan codes to
the legacy convention `0x80 | scan_code`:

| Key      | Byte      | UEFI ScanCode |
|----------|-----------|---------------|
| Up       | `0xC8`    | `0x01`        |
| Down     | `0xD0`    | `0x02`        |
| Right    | `0xCD`    | `0x03`        |
| Left     | `0xCB`    | `0x04`        |
| PageUp   | `0xC9`    | `0x05`        |
| PageDown | `0xD1`    | `0x06`        |
| Esc      | `0x1B`    | `0x17`        |

`hal_getchar_timeout` loops with `Stall(10000)`.

`read_passphrase` ignores NUL returns.

## UI

Framebuffer renderer on top of GOP. No character-cell layer.

`gfx.c` holds the framebuffer and packs 32-bit RGBA to the format the
mode reports. Primitives: fill, alpha blend, vertical gradient,
rounded rectangle, glyph blit. Every primitive clips; out-of-bounds
calls are no-ops, not errors.

`text.c` draws glyphs from `font.c`'s tables. Pen positions on X are
1/4-pixel fixed point; advances are whole pixels, so the fractional
part is always 0 and subpixel variants are unused.

`con.c` keeps the old console API (`con_puts`, `con_putc`,
`con_clear`, `con_set_fg`, `con_read_secret`, `halt`) on top of
`gfx` + `text`. The prompt and short messages go through `con_*`.

`frame.c` draws the panel: rounded rectangle background, 1 px border,
drop shadow, gradient title bar, rows, and a rounded selection
highlight. `menu.c` and `boot.c` call into it.

`theme.c` picks the compile-time theme and is the sole definition of
`theme_current`. Each theme header defines `static const struct theme
theme_values`; `theme.c` includes the one selected by the
`IVO_THEME_*` macro and aliases it.

`font_data.h` is generated by `tools/font_rasterize` from
`assets/NotoSansMono-Regular.ttf`. Layout in `doc/spec.md` §18.

## Filesystem

`fs.h` defines a vtable. `fs_probe_mount()` iterates the driver list
and mounts the first match. Probe order: ext4, btrfs, fat32, iso9660.

### FAT32

Read/write with VFAT long names. FAT loaded into memory at mount. A
30 GB partition with 16 KB clusters has a 7.5 MB FAT; the `.bss` heap
is 1 MiB, so that fails on large ESPs. Real ESPs are small enough
that it does not matter.

`read_sectors` dispatches on `luks_active()`. Sector numbers are
filesystem-relative when LUKS is active.

`fat32_read` coalesces contiguous cluster runs.

The write path is used by TPM enrollment to write `sealed.bin` to the
ESP. Writes bypass the LUKS decryption layer; the ESP is plaintext.

### ext4

Read-only. Handles extents (depth 0 and 1), 64-bit, flex_bg, linear
and htree directories. Refuses `bigalloc`, `meta_bg`, `inline_data`,
`encrypt`, `casefold`, `verity`.

The read path uses two static 4 KiB buffers in `.bss`. No dynamic
allocation except a per-`opendir` handle.

`ext4_bmap` reports run length via `ext4_bmap_run` so
`ext4_read_inode_data` can coalesce consecutive physical blocks.
Before coalescing, a 900 MB file issued one read per 4 KB.

htree lookup gated on `EXT4_INDEX_FL`. A non-indexed directory's
first block starts with `.` and `..` at the same offsets as a
`dx_root`, so a signature-only check would skip the whole directory.

Refuses `s_log_block_size > 4` (block size above 4096).

### BTRFS

Read-only, single-device, uncompressed, subvolumes. Refuses
compressed extents.

Mount reads the primary superblock at offset 0x10000, falls back to
the mirrors on bad CRC, walks the chunk tree, then to the fs tree
root.

`btrfs_read_file` uses `btrfs_chunk_lookup_ex` to coalesce contiguous
physical blocks. Before coalescing, a 900 MB file issued 225,000
reads.

Subvolume selection via `set_subvol` in the driver vtable. See
`doc/btrfs.md`.

### ISO9660

Read-only, Rock Ridge, Joliet, El Torito.

Two I/O modes: block-device and memory. Block-device is what boot uses.

`iso9660_read_label` reads just the PVD volume ID. Used by
`partition_find_iso`.

El Torito: `iso9660_get_boot_catalog` and `iso9660_get_boot_image`,
preferring the UEFI (0xEF) section entry.

Logical sector is 2048 bytes; the HAL counts in 512.

## LUKS

### LUKS1

- Reads the 592-byte header from `boot_lba`.
- Byte-swaps big-endian fields.
- Iterates eight slots. Active means `active == 0x00AC71F3` and
  `stripes >= 2`.
- PBKDF2-HMAC-SHA256 keyslot KDF.
- Keyslot material read from `boot_lba + key_material_offset`
  (absolute).
- AES-XTS decrypt, sector counter starts at 0.
- TKS1 anti-forensic merge (XOR + SHA-256 diffuse per stripe). A flat
  XOR was wrong.
- MK digest is PBKDF2-HMAC-SHA256 truncated to 20 bytes. It used to
  be SHA-1, which was also wrong.

Verified against cryptsetup 2.8.8 via `tests/luks1-test`.

### LUKS2

- Reads the 4 KB header. Version 2 at offset 6. `hdr_size` at offset 8.
- JSON area starts at `boot_lba + 8`.
- JSON parsed with length up to the first NUL.
- Reads keyslot, KDF, and AF sub-objects.
- Argon2id or PBKDF2 keyslot KDF.
- Keyslot material from `boot_lba + area.offset / 512`.
- AES-XTS decrypt with sector counter starting at 0.
- `af.hash` must be `"sha256"`, `af.stripes >= 2`.
- Digest verified against the `digests` object.
- `luks_set_payload(ctx->boot_lba, segments.0.offset / 512)`.

Falls back to the byte-swapped secondary header if the primary JSON
fails to parse.

Verified against cryptsetup 2.8.8 for both KDFs via `tests/luks2-test`.

Argon2id working memory comes from `mm_alloc`, which pulls from the
`.bss` small heap for small requests and falls through to
`hal_allocate_pages` for larger ones.

### Common

- `luks_unlock` dispatches on the version byte.
- `luks_setup_crypto` stores the master key and inits AES-XTS.
- `luks_read_block` reads `part_lba + payload_offset + lba`, decrypts
  with tweak `lba`.
- `luks_read_blocks` chunks at 8192 sectors.

## Partition handling

`try_gpt` reads the GPT header at LBA 1, accepts ESP and Microsoft
Basic Data types. Prefers non-ESP partitions as the boot partition;
the ESP is a fallback only when no other candidate exists.

`partition_find_iso` scans for an ISO9660 partition matching
`iso_label`.

**Retarget.** When the ESP is separate from the LUKS volume,
`hal_init` walks block handles, probes for the LUKS magic, retargets
`g_block_io`, sets `hal_boot_partition_decided`. If no LUKS volume is
found, `g_block_io` stays on the ESP captured from `li->DeviceHandle`.

## Crypto

- AES-256 (`crypto/aes.c`). `inv_mix_columns` uses 4×256-byte
  precomputed Galois tables built at `aes_init`. Replaced a
  bit-by-bit loop; about 10× faster.
- AES-XTS (`crypto/xts.c`).
- SHA-256, SHA-512, SHA-1.
- HMAC-SHA256, HMAC-SHA1.
- PBKDF2-HMAC-SHA256 and PBKDF2-HMAC-SHA1.
- BLAKE2b.
- Argon2id with SSE2 path.
- Ed25519 verify (`ed25519_verify.c` + `fe.c`, `ge.c`, `sc.c`).
- Ed25519 sign and keygen (host-only).

All stack buffers except Argon2's working memory.

SHA-512 padding bug: calling `sha512_update` to pad spins when the
padding crosses a block boundary. Fixed.

## Kernel handoff

### boot_params

On UEFI the kernel's EFI stub builds `boot_params` itself; `boot.c`
passes only the cmdline and initrd.

### Entry

`hal_boot_uefi` in `uefi_kernel.c` does a manual PE/COFF handoff:

1. Parse the PE header. `e_lfanew` at 0x3C, verify `PE\0\0`, read
   `AddressOfEntryPoint` and `SizeOfImage`.
2. `AllocatePages`, zero.
3. Copy each section to its virtual address.
4. Build a static `EFI_LOADED_IMAGE_PROTOCOL` with `ImageBase`,
   `ImageSize`, `SystemTable`, `LoadOptions`, `DeviceHandle`.
5. Install the LoadedImage on a fresh handle.
6. Install LoadFile2 for the initrd.
7. Call the entry point with the Microsoft x64 ABI.

Firmware SB never sees the kernel. Trust anchor is the config's
Ed25519 signature plus `kver`.

Relocations not applied. The Linux EFI stub is PIC with
`ImageBase = 0`.

### Initrd delivery

Two installs, both before the entry point call.

*Global singleton.* Vendor media device path with
`LINUX_EFI_INITRD_MEDIA_GUID` (`5568E427-68FC-4F3D-AC74-CA555231CC68`)
plus `EFI_LOAD_FILE2_PROTOCOL` on the same handle.

*Private on image handle.* `EFI_LOAD_FILE2_PROTOCOL` on the kernel's
own handle under `LINUX_EFI_INITRD_LF2_PROTOCOL_GUID`
(`F9E3378E-B3B1-423A-BD9A-2D0860287F72`). Kernel 6.4+ checks this
first. Stock Artix 7.1.8 does not, but the global install works on it.

`EFI_LOAD_FILE2_PROTOCOL_GUID` is
`4006C0C1-FCB3-403E-996D-4A6C8724E06D`. Kernel source and tianocore
both define `E06D`. Ivo had `E0DE`; every `LocateDevicePath`,
including Ivo's own self-test, searched for the wrong value. One byte.

`LoadFile` returns `EFI_BUFFER_TOO_SMALL` with the size on a null or
undersized buffer; copies on a large enough one. Kernel calls twice.

`initrd=` on the cmdline also works via
`EFI_SIMPLE_FILE_SYSTEM_PROTOCOL`, resolved against the loaded
image's volume.

If neither delivers an initrd, the kernel boots without one and
panics at `prepare_namespace` with
`VFS: Unable to mount root fs on unknown-block(0,0)`.

### Debugging the handoff

When the kernel runs but never calls `LoadFile`, the fault is on the
kernel side and not observable from Ivo. Three tools:

1. Debug OVMF with `-D DEBUG_ON_SERIAL_PORT`.
2. A kernel with COM1 markers in `efi_load_initrd` and
   `efi_load_initrd_dev_path`
   (`drivers/firmware/efi/libstub/efi-stub-helper.c`).
3. `efi=debug` and `earlycon=` on the cmdline, requires
   `CONFIG_EFI_EARLYCON=y`. Stock Artix 7.1.8 does not enable it.

Byte-grepping a compiled binary for a GUID does not work. `-O2`
splits 16-byte constants across `movabs`.

### Chainload

`hal_chainload` loads a second EFI binary. Same-volume only.
The caller already verified the hash against `cver`.

Builds a device path from the outer Ivo's volume DP plus a synthetic
`FilePathDevicePath` node (`\ivo-chain`) plus `END_ENTIRE`. The
synthetic path is never read; bytes are supplied directly.

SB policy applies. Target must be signed against `db`.

`StartImage` may return. `hal_chainload` returns 0 so `boot_entry`
falls through.

Each chainloaded instance is a fresh process with its own `g_st`,
`g_image`, `g_block_io`. No shared LUKS state.

## Configuration

TOML subset: global keys, then `[entries.<name>]` sections. No arrays,
nested tables, or inline tables.

Sources:

1. If `IVO_EMBEDDED_CONFIG` is defined, the config is a compiled-in
   string generated by `tools/mkinitivo`.
2. Otherwise, `/ivo/config.toml` on the boot filesystem.

Same parser both ways.

### Fields

Global:

- `timeout = <int>` — countdown seconds.
- `default = "<name>"`.

Per entry:

- `kernel`, `initrd`, `options`
- `kver`, `iver` — SHA-512 hex, filled by `ivo-sign --hash`
- `type = "linux"` (default), `"efi-chainload"` or `"iso-boot"`
- `path`, `cver` — chainload target and its hash
- `iso_label` — volume ID of the ISO partition, for `iso-boot`
- `subvol`, `hidden = true|false`, `timeout = <int>`

The grammar is strict and shared with the tools (`boot/config.c` is
linked into `ivo-sign`, `ivo-doctor`, `ivo-config`, `ivo-convert`):
string values must be quoted and closed, lines may not exceed 4095
bytes, unknown or duplicate keys and duplicate entry names are errors,
hashes are empty or 128 lowercase hex digits. Key order inside an
entry does not matter.

## LVM

Reads PV label, MDA header, metadata text. Linear segments only. No
striping, mirroring, or thin pools.

`extent_size` and `pe_start` are in 512-byte sectors in the metadata,
not bytes. Both multiplied by 512.

`lvm_read_blocks` dispatches to LUKS or HAL. Coalesce cap: 8192
sectors.

## Boot menu

`menu.c` — numbered list, timeout, default entry. Arrow keys, Enter,
Esc, digits 1–9. The menu always draws, even with one entry.

Countdown is `Stall`-based. `hal_getchar_timeout` is non-blocking.

## Shell

`ls`, `cat`, `stat`, `entries`, `boot`, `disk`, `clear`, `reboot`,
`halt`, `exit`, `help`. Read-only.

## TPM

`tpm.c` measures PCRs 8 and 9 via `EFI_TCG2_PROTOCOL`.
`HashLogExtendEvent` hashes and extends.

`EFI_TCG2_EVENT` under `#pragma pack(1)`:

```
uint32_t Size;
uint32_t HeaderSize;      // 14
uint16_t HeaderVersion;   // 1
uint32_t PCRIndex;
uint32_t EventType;
uint8_t  Event[1];
```

Minimum 19 bytes. Pass `Flags = 0` and let firmware hash. Wrong layout
produces `EFI_INVALID_PARAMETER`.

Direct CRB MMIO does not work under SMM. Reads return `0` or
`0xFFFFFFFF`.

`tpm_seal_create.c` handles the enrollment half: creates the SRK at
`0x81000001` if it does not exist, builds the auth policy via a trial
session, creates the sealed object, emits the blob. Enrollment
triggered by a zero-byte `/EFI/ivo/seal-request` file on the ESP.

## Secure Boot

| Layer | Mechanism | Verified by | Key |
|---|---|---|---|
| Firmware → Ivo | Authenticode | OVMF | X.509 RSA-2048 in `db` |
| Ivo → config | Ed25519 | `secure_boot.c` | Ed25519 pubkey compiled in |
| Ivo → cmdline | signed config | `secure_boot.c` | same sig |
| Ivo → kernel | SHA-512 | `boot.c` (`kver`) | hash in config |
| Ivo → initrd | SHA-512 | `boot.c` (`iver`) | hash in config |
| Ivo → chainload | SHA-512 + Authenticode | `boot.c` + OVMF | hash + db |

Kernel layer verified by hash only; the manual handoff bypasses
firmware SB.

`secure_boot.c`:

- `sb_read_config` — reads config and sig once, Ed25519 against the
  compiled-in pubkey, returns the verified buffer for parsing.
  Failure is `panic("config.toml signature invalid")`.
- `sb_hash_buffer` — SHA-512 to lowercase hex.
- `sb_hash_matches` — constant-time hex compare.

No-op without `SECURE_BOOT`. `secure_boot_pubkey.h` generated by
`tools/ivo-keygen`. Not in the repo; regenerate per machine.

## Build system

Single `Makefile`. `config.mk` toggles (`LUKS`, `LUKS_USE_ARGON2`,
`LVM`, `TPM`, `SECURE_BOOT`), `THEME`, `GFX_FMT`. All `?=`.

**UEFI:** `nasm -f win64`, `x86_64-w64-mingw32-gcc`. `-DIVO_UEFI`,
`-fshort-wchar`, `-mno-stack-arg-probe`. Feature flags must reach
`CFLAGS_EFI`; an earlier Makefile added `SECURE_BOOT` only to `CFLAGS`
and the UEFI build ignored it.

`GFX_FMT` maps to `-DIVO_GFX_FMT_<NAME>`; `THEME` maps to
`-DIVO_THEME_<NAME>`. `make clean` is required when either changes.

`uefi_kernel.c` added to the source list explicitly.

`ed25519_sign.c`, `ed25519_keypair.c`, `ed25519_seed.c` filtered out.

`-MMD -MP` for dependency tracking.

`install` and `uninstall` targets take `ESP=`.

**Tools:** `mkinitivo`, `keymap_compiler`, `ivo-sign`,
`ivo-keygen`, `ivo-convert`, `ivo-install`, `ivo-config`,
`ivo-doctor`, `font_rasterize`.

**Tests:** `luks1-test`, `luks2-test`, `btrfs-test`, `sha512-test`,
`ed25519-test`.

## Status

**Works.**

- UEFI: `EFI_BLOCK_IO_PROTOCOL` with LUKS retarget, ESP fallback when
  no LUKS volume is present.
- `GetMemoryMap`.
- FAT32, ext4 (htree, run coalescing), BTRFS (single-device,
  subvolumes, run coalescing), ISO9660 (Rock Ridge, Joliet, El
  Torito).
- Filesystem probe by superblock magic.
- TOML config from disk or embedded.
- LUKS1, LUKS2 with PBKDF2 and Argon2id.
- UEFI manual PE handoff.
- LoadFile2 initrd delivery.
- Framebuffer UI: panel, title bar, selection highlight, footer.
  Five compile-time themes.
- End-to-end: UEFI boots LUKS2+ext4 install.
- End-to-end: UEFI+SB boots signed bootloader, unsigned kernel via
  manual handoff.
- End-to-end: UEFI+SB boots Alpine 3.21.3 live ISO to login.
- End-to-end: btrfs with subvolumes, default subvolume set, config in
  `@/ivo/`, kernel+initrd in `@/alpine/`.
- End-to-end: USB built by `ivo-install --target usb` boots Alpine
  live on real hardware (H310M/i5-9400F).
- Chainload (UEFI+SB): nested Ivo boots a kernel.
- SHA-512: FIPS vectors + boundary cases.
- Ed25519: RFC 8032 §7.1 vectors.
- Secure Boot: firmware Authenticode + Ed25519 config + per-entry
  SHA-512.
- TPM measurement: PCRs 8, 9 via TCG2 under SMM, verified with swtpm.
- TPM enrollment: `seal-request` trigger, blob written to the ESP,
  prompt skipped on next boot.

**Doesn't work.**

- ext4 extent depth 2.
- Chainload to non-Ivo EFI binaries untested.
- PE relocations unsupported.
- No LVM striping.
- No LUKS inside an LV.
- Wrapped LVM MDAs are refused.
- LUKS1 backup header not read.
- Rock Ridge: supported for reading, but POSIX metadata (permissions,
  symlinks) not applied.
